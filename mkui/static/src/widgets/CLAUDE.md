# mkui/static/src/widgets — dialog fields

Moved out of the root CLAUDE.md (40,000-character cap). The rest of the dialog — frame, sections, pinning, keys, message boxes — is still described there.

## Fields, options and submit

`spec.fields` items: `{ group }` headers, `{ row: [...] }` rows (`width` = flex share), or fields (types: README; temporal fields are native pickers, values canonical: `datetime` a UTC ISO instant via `lib/timeparse.js`, `parse`/`tz` read other formats; `time: "optional"` pairs date + time in `.mkui-dialog-datetime`, a bare date while time is blank). `optionsFrom` re-fetches when a `${field.X}` param moves (`fill = { field: column }` on that select copies the picked row into named fields via `applyFill`, blanks skipped, targets `dirty`; `remember = key | { key, value }` stores the field, or `value`'s result, in `extra.storage`/localStorage on a confirmed submit, `recallAll` restoring it at open/reset), `optionsFromColumn` takes table values. `spec.submit.service` sends via `client.send()` (5s timeout; `submitPerRow` = one request per selected row merged with `rowData`), errors inline; else resolves at once. `submit.then = { action, args }` → `follow(data)` per confirmed submit: `app.fireAction(args)` over `{ ...context, ...data, form: data }`. `_`-prefixed names never submit. Fields need no `name`: `fieldState` keys by name, the DOM by `keyOf(f)`.

## Added in 1.11.0

- **`type: "checklist"`** — a scrolling box of tick boxes over `options` or `optionsFrom`, for choosing several records at once. Its value is a **string**: the ticked values joined by commas, in list order, `""` for none (`checklistParse` / `checklistFormat` / `checklistState`, exported and node-tested). That keeps it on the dialog's existing rails: `required` means "tick at least one", `remember`, `showWhen`/`required` expressions over it (`CONTAINS(what, 'x:')`) and the submit payload need nothing new, and the server splits on the comma — so option values must not hold one. `value: "*"` opens with every row ticked, including rows a fetch brings later; `all: "label"` adds a sticky first row that ticks or clears everything and is `indeterminate` while only some are; `size` = rows in view (default 8, 2–40); `none` = the text of an empty list. Built by `buildChecklist` (the element carries `_mkuiSet`, `_mkuiOptions`, `_mkuiValue`); `fetchChecklist` is its `optionsFrom` fetch, called at build and from `refreshDependentOptions`. It has no `fill`. Rows are `<label>`s, so the stylesheet must undo the dialog's full-width `input` rule for the tick boxes (tested).
- **A select's `size`** (2–40, `listRows`) renders it as a list box (`.mkui-dialog-listbox`) instead of a dropdown. Still one value.
- **`optionsFrom.empty`** (`emptyLabel`, a template) names the blank choice a fetched select opens with; a dash otherwise. A static `options` list is **not** merged into a fetched one and never was — an app that wrote one for its blank row was showing the dash.

## A field named after the context

The form's fields shadow the opening context (`formScope`: `{ ...context, ...vals, form }`), by design — but a field named `row`, `rows`, `cell`, `cells`, `selection` or `state` (`CONTEXT_NAMES`) takes that name from every expression in the dialog, silently: mkfix's Macro… dialog kept the selection's ids in a hidden `rows`, and its title's `LEN(rows)` counted the characters of the list. `shadowedNames(spec)` finds such fields — named after a context name **and** in a spec whose expressions read it (`specNames`: every `${…}` and every `EXPR_KEYS` expression, through the compiled `fieldRefs`, so a lambda's or LET's own names do not count) — and `openDialog` warns once per dialog (`spec.id ?? spec.title`) and name. A State field in a form that never says `state` is left alone, and so are the opener's own context keys (`{ name: "AAPL" }`): only the names mkui hands out. It is a warning, not a refusal: nothing about the dialog changes. `tests/dialog.test.js` has the cases.
